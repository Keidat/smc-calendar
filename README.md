# 세명 스쿨캘린더

세명컴퓨터고등학교 학사일정과 학급일정을 보여 주는 한국어 반응형 웹 앱입니다. Python 3.13 이상과 브라우저만 있으면 실행할 수 있습니다. 외부 패키지, 유료 DB, 빌드 과정이 없습니다.

## 실행

PowerShell에서:

```powershell
cd C:\code\github_sky\smc-calendar
python server.py
```

http://127.0.0.1:8000 접속. 학사일정은 공개, 학급일정도 비로그인 상태에서 모든 학생 학급을 조회할 수 있습니다. 학생은 소속 학급에만 등록하고 자신의 일정만 수정·삭제합니다. 달력과 데이터베이스는 빈 상태로 시작하며, 실제 학교 일정은 포함하지 않습니다.

Windows에서는 `start.ps1`을 실행해도 됩니다. 서버는 첫 실행 때 프로젝트 폴더 안에 `school.db`를 자동 생성합니다. 실행 위치가 달라도 데이터 파일은 항상 `server.py` 옆에 저장됩니다.

## 다른 PC로 이전하기

1. 실행 중인 서버를 Ctrl+C로 종료합니다.
2. **smc-calendar 폴더 전체**를 USB 등으로 새 PC에 복사합니다. `school.db`(회원·일정·인증 정보), `config.json`(학교 도메인·학급 설정), `.env.local`(메일 서버 설정)을 빠뜨리지 마세요. 최초 실행 전에는 이 파일들이 없을 수 있습니다.
3. 새 PC에 Python 3.13 이상을 설치합니다. 별도 DB 서버나 Python 패키지는 필요 없습니다.
4. 복사한 폴더에서 `python server.py`를 실행하고 http://127.0.0.1:8000 에 접속합니다. 경로를 C:\code로 맞출 필요는 없습니다.

`school.db`에 데이터가 저장되므로 기존 회원과 일정이 유지됩니다. 두 PC의 DB를 동시에 수정해도 자동 동기화되지는 않습니다. `.env.local`을 함께 옮기면 SMTP 설정도 유지되지만, 새 PC의 네트워크에서 메일 서버 연결이 허용되어야 합니다. 해당 파일과 DB에는 민감한 정보가 있으므로 안전한 경로로 전달하세요.

실행 중 DB를 백업하려면 `python backup.py`를 사용하세요. SQLite backup API로 일관된 복사본을 `backups/날짜-시간/school.db`에 저장하며 학교 설정도 함께 복사합니다. 복원은 서버를 종료한 뒤 백업의 `school.db`와 `config.json`을 프로젝트 폴더에 복사합니다. 현재 DB를 따로 보관한 후 덮어쓰세요. 메일 설정은 백업에 포함되지 않습니다.

## 실제 이메일 인증 설정

사용 가능한 SMTP 발송 계정이 필요합니다. 계정 제공자가 무료 발송을 허용하면 앱 자체에는 비용이 발생하지 않습니다. 학교 이메일의 **수신 도메인**과 메일을 보내는 **SMTP 계정**은 서로 다를 수 있습니다. 학교 측의 외부 인증 메일 수신 허용 여부를 확인하세요. 무료 호스팅 또는 SMTP의 정책·한도는 제공자에 따라 다릅니다.

```powershell
$env:SMTP_HOST = '사용할 SMTP 서버 주소'
$env:SMTP_PORT = '587'
$env:SMTP_USER = '발신 계정'
$env:SMTP_PASSWORD = '발신 계정의 앱 비밀번호 또는 SMTP 비밀번호'
$env:SMTP_FROM = '발신 이메일'
python server.py
```

587은 STARTTLS, 465는 TLS 연결입니다. 인증 코드는 랜덤한 6자리 숫자이며 10분 유효, 5회 시도 제한, 60초 재발송 간격을 적용합니다. 해시만 DB에 저장합니다. SMTP 미설정/실패 시 가입을 우회하거나 코드를 화면에 표시하지 않습니다. 환경변수 비밀번호를 Git에 저장하지 마세요.

PC 이전을 편하게 하려면 `.env.example`을 `.env.local`로 복사해 값을 입력하세요. 서버가 자동으로 읽으며 이미 지정한 환경변수가 있으면 환경변수를 우선합니다. 이 설정 파일은 프로그램 코드가 아닌 일반 텍스트(KEY=VALUE)이며, 빈 SMTP_HOST 상태에서는 메일을 보내지 않습니다.

## 최초 관리자

```powershell
python server.py --create-admin
```

현재 프로젝트 DB는 요청에 따라 기존 계정을 삭제하고 **아이디 `admin`, 비밀번호 `admin`**인 관리자 한 명으로 초기화했습니다. 이 계정의 이메일은 `semyeong.calendar@gmail.com`입니다. 서버를 다시 시작해도 계정을 반복 초기화하지 않습니다. 새 PC로 DB를 옮기면 이 계정도 함께 유지됩니다. 위 명령은 추가 관리자를 만들 때 사용하며 아이디와 비밀번호를 입력합니다. 운영용 관리자 생성은 이메일 인증 과정의 예외이며, 일반 회원가입은 학교 이메일 인증이 필수입니다.

회원가입은 아이디(영문·숫자·밑줄 4~30자), 실명, 학교 이메일, 인증 코드, 학급, 비밀번호 및 비밀번호 확인를 입력합니다. 로그인에는 이메일 대신 아이디를 사용합니다. 일반 회원가입 비밀번호는 8~128자이며 요청한 초기 관리자 `admin`만 이 길이 규칙의 예외입니다. 로그인한 사용자는 상단 개인정보 버튼에서 자신의 정보를 확인하고 비밀번호 오른쪽 수정 버튼을 누를 수 있습니다. 현재 비밀번호·새 비밀번호·새 비밀번호 확인을 검증하며 변경 후 모든 세션을 종료합니다. 닉네임은 현재 사용하지 않고 실명으로 표시합니다. 실명과 학급 등은 관리자만 수정할 수 있습니다. 관리자는 아이디도 수정할 수 있습니다.

좌측 관리자 문의 메뉴에서 로그인 후 제목과 내용을 작성하면 SMTP 설정을 이용해 `semyeong.calendar@gmail.com`으로 전송합니다. 계정 이메일을 Reply-To에 넣고 아이디·실명·학급을 본문에 포함합니다. 전송 성공/실패 상태는 SQLite inquiries 테이블에도 보관합니다. 메일 실패는 성공으로 안내하지 않으며 자동 재전송은 제공하지 않습니다. 문의 발송은 사용자당 10분에 5회로 제한됩니다.

관리자 로그인 후 좌측 관리자 메뉴에서 회원 조회·아이디/실명/학급/권한/비밀번호/이메일 수정과 허용 도메인 관리를 할 수 있습니다. 이메일 변경은 새 주소로 전송된 인증 코드가 필요합니다. 학사일정 및 학급일정도 등록·수정·삭제할 수 있습니다. 각 관리자 API 요청에서 비밀번호를 다시 검증하며, 별도의 관리자 인증 유효기간을 두지 않습니다. 비밀번호 해시와 인증 코드·세션은 회원 목록에 노출하지 않습니다. 관리자 조작 기록은 DB의 audit 테이블에 저장됩니다.

## 학급과 도메인

초기 학급은 **임시로 1~3학년, 각 1~10반**을 제공합니다. 실제 학교 편제를 확정한 값이 아닙니다. 사용 전에 프로젝트의 `config.json`을 아래 형태로 만들어 실제 학급을 지정하세요. 관리자 도메인 저장 시에도 이 파일이 생성됩니다.

```json
{
  "domains": ["smc.sen.hs.kr"],
  "classes": ["1학년 1반", "1학년 2반", "2학년 1반", "3학년 1반"]
}
```

회원 학급은 관리자만 변경합니다. 도메인은 관리자 화면에서 쉼표로 구분해 추가할 수 있습니다. 도메인 변경은 신규 인증에 적용되며 기존 회원 로그인에는 영향을 주지 않습니다.

## 일정 입력과 확장

사용자가 제공한 2026. 4. 14. 안내 이미지의 2026학년도 학사일정을 `school.db`에 입력했습니다. 검토용 데이터는 `data/school-2026.json`에 있습니다. 2026년 3월부터 2027년 1월까지 70개의 날짜별 일정이며, 기간 행사는 날짜별로 나누고 10월 정기시험은 원문의 수업일(15·16·19일)에 표시합니다. 원문에 기재된 보강 수업 날짜도 반영했습니다. `python import_school_2026.py`를 실행하면 같은 날짜·제목의 학사일정은 중복 추가하지 않습니다. 기존 일정과 회원정보는 유지합니다.

실제 데이터를 받으면 관리자 계정의 '일정 등록'에서 학사일정을 넣을 수 있습니다. 제목, 날짜(YYYY-MM-DD), 상세 내용, 구분(school/class), 학급을 사용합니다. 이 버전은 수동 입력을 제공하며 홈페이지 자동 수집/CSV 일괄 가져오기는 아직 포함하지 않습니다. 급식 조회는 구현되어 있으며 시간표는 예정 안내만 표시합니다.

## 확인

```powershell
python -m unittest discover -s tests -v

```

테스트는 임시 DB와 메일 발송 모의 함수를 사용하며, 네트워크 없이 HTTP 요청 처리 함수를 직접 실행합니다. 실제 브라우저 접속과 SMTP 발송은 실행 환경 및 실제 수신함에서 별도로 확인해야 합니다.

## 운영 범위

학교 개인 프로젝트의 로컬 실행용 서버입니다. 기본적으로 127.0.0.1에만 바인딩됩니다. 다중 사용자를 위한 인터넷 운영 시에는 HTTPS 역방향 프록시와 운영용 서버 구성이 필요합니다. HTTPS 환경에서 `COOKIE_SECURE=1`을 설정하세요. 표준 라이브러리 HTTP 서버는 공개 서비스 운영용으로 설계된 서버가 아닙니다. SQLite 파일에 회원정보가 있으므로 접근 권한과 백업을 관리하세요. 비밀번호 찾기, 회원 탈퇴, 자동 메일 재시도, 학기별 반 이동은 현재 범위에 포함되지 않습니다.

가입 화면에서 학생·교사를 선택하며 기본값은 학생입니다. 교사 선택 시 관리자 문의 주소를 안내하고 직접 가입은 차단합니다. 관리자는 회원정보 수정 화면에서만 관리자·교사 학급 항목을 선택할 수 있습니다. 이 항목은 공개 달력과 일반 가입의 학급 목록에서 제외합니다. 관리자 페이지는 달력 영역을 대체하며, 관리자 권한 작업의 비밀번호 재인증은 유지합니다.

## 문의 회신과 알림
관리자는 문의 조회 때 재인증하며, 문의 본문과 이메일 발송 상태를 확인하고 회신할 수 있습니다. 회신은 작성자의 알림함에만 전달됩니다. 관리자 전체 알림은 현재 모든 회원의 알림함에 전달됩니다. 상단 알림 버튼에 미확인 개수가 표시되며 30초마다 갱신됩니다. 각 사용자는 본인의 알림만 읽고 읽음 처리할 수 있습니다. 이메일 전달에 실패해도 사이트 문의 접수는 완료됩니다. 관리자 메일 회신을 자동 수집하는 기능은 없으며 사이트에서 작성한 회신만 알림함에 반영됩니다.

관리자와 교사는 모든 학사일정 및 모든 학급일정을 등록·수정·삭제할 수 있습니다. 교사는 회원정보·문의·도메인 관리 권한이 없습니다. 관리자 작업의 비밀번호 재인증은 유지합니다. 마지막 관리자는 학생이나 교사로 변경할 수 없습니다.

## 일정 상세 화면과 대표 댓글
달력의 일정 이름 또는 오른쪽 일정 목록의 항목을 클릭하면 중앙 일정 목록과 오른쪽 댓글 화면으로 전환합니다. 달력은 화면 오른쪽 아래의 작은 달력으로 유지되며 날짜·월을 바꾸거나 확대 아이콘으로 큰 달력으로 복귀할 수 있습니다. 우클릭은 브라우저 기본 동작을 유지합니다. 모바일에서는 목록 아래에 댓글을 배치합니다.

좋아요는 로그인한 사용자마다 댓글당 한 번이며 취소할 수 있습니다. 대표 댓글은 고정 댓글 우선, 없으면 좋아요가 1개 이상인 최다 추천 댓글입니다. 동점이면 먼저 등록된 댓글을 표시합니다. 고정은 교사·관리자만 할 수 있고 일정당 1개로 제한합니다. 관리자의 고정·해제에는 재인증이 필요합니다. 고정 해제·댓글 삭제·좋아요 취소 시 대표 댓글을 다시 선택합니다. 대표 댓글의 본문은 공개 일정 상세에서도 보이며 전체 댓글 조회·작성·좋아요는 로그인이 필요합니다. 데이터는 school.db의 comments 및 comment_likes 테이블에 저장됩니다.

## 급식 조회
왼쪽 급식 메뉴에서 로그인 없이 날짜별 메뉴·칼로리·영양 정보·원산지를 확인합니다. 학교는 나이스 학교기본정보에서 서울 소재 세명컴퓨터고등학교를 조회해 확인합니다. 식단이 없을 때와 API 오류를 별도로 안내합니다. 서버 메모리에 정상 식단은 1시간, 미등록 결과는 10분 동안 캐시합니다.

나이스 인증키는 `.env.local`의 `NEIS_API_KEY`에 설정합니다. 브라우저나 공개 API 응답에 키를 포함하지 않습니다. 설정 변경 후 서버를 재시작하세요. 새 PC로 이전할 때 `.env.local`도 안전하게 함께 옮기세요. 인증키 미설정 시 나이스 샘플 조회(최대 5건)를 사용합니다. 실제 급식 API 연결 및 학교 조회는 확인했으며 브라우저 화면 검증은 별도로 필요합니다.

## 가입 검증과 비밀번호 복구
회원가입 아이디는 입력 후 사용 가능 여부를 확인하고 비밀번호 확인은 입력 중 일치 여부를 표시합니다. 최종 가입 시 서버에서도 아이디 중복과 비밀번호 확인을 검사합니다. 로그인 화면의 비밀번호 복구에서 가입한 아이디와 학교 이메일을 입력한 뒤 복구 코드를 받아 새 비밀번호를 설정합니다. 복구 코드는 가입 코드와 별도 테이블에 보관하고 10분 유효·5회 시도·60초 재전송 제한을 적용합니다. 복구 성공 시 코드를 폐기하고 기존 모든 세션을 종료합니다. 이메일 전송은 SMTP 설정을 사용합니다. 가입 주소가 허용 학교 도메인에 해당하는 계정에서 복구할 수 있습니다. 댓글 내용이 실제로 변경되면 수정 시각을 저장하고 댓글에 수정됨을 표시합니다.

## 학교 이메일 간 중복 가입 방지
학교에서 안내한 학생 이메일 규칙을 이용해 `24s209@smc.sen.hs.kr`과 `24s209h0659@sonline20.sen.go.kr`의 공통 학생 식별자 `24s209`를 동일인 키로 저장합니다. 원래 입학 시 정보이므로 현재 학급 선택과 독립적입니다. DB의 school_identity UNIQUE 인덱스와 서버 검사로 다른 아이디·다른 실명을 입력해도 동일 식별자 중복 가입을 차단합니다. 동명이인은 식별자가 다르면 가입할 수 있으며 실명 UNIQUE 제약은 없습니다. 교사(t) 이메일과 안내된 패턴 외의 이메일은 학생 식별자를 추정하지 않습니다. 새로운 도메인을 추가할 때에는 해당 도메인의 학생 식별자 규칙도 별도로 구현해야 합니다. 관리자 이메일 변경 시에도 타 계정과의 식별자 충돌은 막고, 해당 계정 본인의 다른 학교 이메일로 변경하는 것은 인증·재인증 후 허용합니다. 기존 DB에 동일 식별자 계정이 복수로 있으면 자동 삭제하지 않고 관리자 정리가 필요하다는 오류로 중단합니다.

## 이메일 알림 및 개인 발송
관리자 문의 회신과 회원 알림은 사이트 알림함 및 가입 이메일로 함께 전송합니다. 회원 알림의 수신 대상은 전체 회원 또는 개인입니다. 개인 수신자 목록은 관리자 재인증 후 불러옵니다. 이메일 발송 실패 시에도 사이트 알림은 보존하며 notifications.email_status에 sent/failed를 저장하고 관리자 화면에 전송·실패 건수를 안내합니다. 이메일 발송 실패의 자동 재시도는 제공하지 않습니다. 기존에 사이트로만 보냈던 과거 알림은 자동으로 재발송하지 않습니다. 전체 발송은 이메일별로 순차 처리하므로 완료될 때까지 기다려 주세요. SMTP 인증정보와 나이스 키는 .env.local에서 읽습니다.

## 수신자 검색과 발송 진단
회원 목록 및 수신자 검색은 이름·아이디·이메일과 학급 필터를 지원하며 페이지당 30명을 표시합니다. 수신자는 여러 페이지에서 체크할 수 있으며 검색 변경 후에도 선택을 유지합니다. 선택한 회원 또는 명시적인 전체 회원을 대상으로 발송합니다. 새 기능을 지원하지 않는 구 서버가 실행 중이면 일괄 발송을 차단하고 재시작 안내를 표시합니다.

관리자는 최근 100건의 이메일 발송 내역에서 발송 미시도·실패·SMTP 접수 상태와 안전한 오류 요약을 확인합니다. 미시도 또는 실패 건만 이메일을 재시도할 수 있으며 사이트 알림을 중복 생성하지 않습니다. SMTP 접수는 실제 받은편지함 도착을 보장하지 않으므로 학교 수신 차단이나 스팸함도 확인해야 합니다.

## 문의 이미지 첨부
문의 작성 창에서 파일 선택 또는 클립보드 이미지 붙여넣기(Ctrl+V)를 지원합니다. 최대 3장, 이미지당 2MB이며 PNG/JPEG/GIF/WebP 형식만 허용합니다. 전송 전 미리보기에서 개별 제거할 수 있습니다. 브라우저에서 내용을 읽어 전송하고 서버에서 용량 및 파일 서명을 검사합니다. SVG는 허용하지 않습니다. 첨부 원본은 inquiry_attachments 테이블에 저장되어 DB 백업·이전 시 함께 유지됩니다. 이메일에도 동일 이미지를 첨부하고, 발송 실패 시에도 사이트 문의와 이미지는 보존합니다. 이미지 URL은 로그인한 문의 작성자 또는 관리자만 접근할 수 있습니다. 관리자 문의함과 회신 창의 원래 문의에서 썸네일을 확인하고 누르면 원본을 새 탭으로 열 수 있습니다.
